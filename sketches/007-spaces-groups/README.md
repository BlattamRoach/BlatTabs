# 007 — Пространства и группы

## Статус: прототип (дизайн-скетч), ещё не в приложении

Интерактивный прототип новой организации вкладок: **пространства** (spaces) вместо
строки «Все» + папок, и **сворачиваемые группы** внутри пространства. Само-
до-статочный файл, открывается двойным кликом (file://), без chrome API, данные —
инлайн-массивы в JS. Визуально повторяет текущий дизайн приложения
(`theme.css` / `view.html`: Vercel-монохром, Geist + Geist Mono, 1px линии через
box-shadow, компактные карточки, чернильный акцент на активном чипе).

## Что прототипируется

1. **Пространства** — строка чипов под шапкой. Каждый сохранённый таб обязан
   принадлежать ровно одному пространству (`spaceId` обязателен в модели).
   Клик по чипу фильтрует сетку; активное пространство выделено чернилом.
   Чипа «Все» нет — активное пространство по умолчанию первое.
   «+ Пространство» (пунктирный чип, как «+ Папка») → модалка имени
   (пустое имя → «Пространство N»); новое пространство становится активным
   и показывает пустое состояние «Пока пусто».
2. **Группы внутри пространства** — именованные, необязательные
   (`groupId` опционален). Группа рендерится секцией: полноширинная шапка
   (chevron ▾/▸ + имя + mono-счётчик «N вкладок») и карточки-члены.
   Шапка всегда видна; клик по ней сворачивает/разворачивает (карточки
   уходят из DOM, счётчик на шапке остаётся). Негрупповые вкладки рендерятся
   обычными карточками после всех групп (с подписью «Без группы»).
   Порядок групп = порядок в массиве.
3. **Управление группами** — на карточке (по hover) кнопка-папка (как у
   текущего дропдауна переноса папок): «Без группы», все группы активного
   пространства, «+ Новая группа…» (модалка имени; группа создаётся в
   активном пространстве развёрнутой, карточка переносится в неё).
   На шапке группы — «✕» (с confirm()): группа удаляется, её вкладки
   становятся негрупповыми.
4. **Поиск** — функциональный: фильтрует видимые карточки активного
   пространства (совпадение по имени/URL); шапки групп остаются, скрытые
   члены исключаются, группа без совпадений схлопывается в одну шапку.
   Свёрнутая группа во время поиска тоже не показывает членов
   (фильтруются именно *видимые* карточки).
5. **Клик по карточке** — no-op (только `console.log('open', url)`); из
   file:// контекста нечего открывать.
6. 🌙/☀️ — переключатель тёмной/светлой темы (токены из theme.css).

## Модель данных (инлайн в index.html)

```js
spaces: [{ id, name }]
groups: [{ id, name, spaceId, collapsed: bool }]
tabs:   [{ id, name, title?, url, spaceId /* обязательный */, groupId /* опциональный */ }]
```

Фавикон — буквенный fallback приложения (первая буква домена, mono-плитка),
как в текущем `view.html`. Демо-состояние: «Работа» (группы «Мониторинг»
[3, раскрыта] и «Документы» [2, свёрнута] + 2 без группы), «Проекты»
(«Идеи» [2, раскрыта] + 2 без группы), «Дом» (2 без группы).

## Явно вне скоупа прототипа

- Клавиатурная навигация по сетке, режим выбора, массовое открытие.
- Экспорт/импорт, drag-and-drop, перенос между пространств.
- Персистентность — состояние сбрасывается при перезагрузке (это ок для
  прототипа); реальный стейт будет в `chrome.storage`.
- Popup-поток сохранения вкладок и обязательное назначение пространства
  *при сохранении* (модель уже требует `spaceId`; save-UX — отдельная задача).
- Пустые пространства удалять нельзя (нет UI), группы нельзя переименовывать,
  порядок групп/пространств менять нельзя — всё это в последующих итерациях.
