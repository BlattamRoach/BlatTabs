# BlatTabs — расширение для управления сохранёнными вкладками

Браузерное расширение Chrome (Manifest V3), менеджер сохранённых вкладок, вдохновлённый toby.io / Taby. Заменяет страницу новой вкладки на свою — при Ctrl+T или клике по «+» в браузере открывается BlatTabs с сохранёнными вкладками.

## Архитектура

```
manifest.json          — Manifest V3, chrome_url_overrides.newtab → view.html
background.js          — Service worker: CRUD вкладок/пространств/групп, миграция legacy-папок
popup.html / popup.js  — Popup: «Сохранить вкладку» с выбором пространства
view.html / view.js    — Страница новой вкладки (newtab override): пространства, группы, карточки
i18n.js                  — RU/EN-словарь строк интерфейса + переключатель языка (blattam-lang в chrome.storage.local)
theme.css              — дизайн-токены (CSS-переменные), общие для view и popup
icons/                 — иконки расширения: icon16.png / icon48.png / icon128.png
build_zip.py           — сборка dist/BlatTabs-v<версия>.zip для Chrome Web Store (только stdlib)
update.json            — фид автообновления (manifest `update_url`): версия + URL свежего zip в releases/
releases/              — zip-релизы автообновления (BlatTabs-v<версия>.zip; отдаёт GitHub Pages, default branch)
store/                 — материалы магазина: DESCRIPTION.md + 3 PNG-макета
```

### Хранилище

Ключ `blattam-tabs`, элементы формата:
```js
{ name, url, title?, favIconUrl?, comment?, spaceId (обязательно), groupId? }
```
`favIconUrl` — URL фавикона сайта (ставится при сохранении через popup/hotkey, если у вкладки он есть; data: URL тоже допустим; без него — поле отсутствует, в view отрендерится буквенный fallback). `groupId` — группа внутри пространства (отсутствует/null — вкладка вне групп). `comment` — свободный комментарий к вкладке: показывается внизу внутри карточки (моно, обрезается); пустой/отсутствующий — поле не ставится (из записи уходит сам ключ).

Ключ `blattam-spaces` — пространства (плоские, без вложенности):
```js
{ id, name }
```
Первое по умолчанию — «Мои вкладки». Дубли по имени (без учёта регистра) не создаются.

Ключ `blattam-groups` — сворачиваемые группы внутри пространств:
```js
{ id, name, spaceId, collapsed }
```
Группы плоские, живут в одном пространстве. Пустая группа рендерится с «0 вкладок». Группа, потерявшая последнюю вкладку, автоматически сворачивается (collapsed: true — шапка с «0 вкладок», без строки «Перетащите вкладку сюда»); пустая группа никогда не раскрывается: всегда рендерится в свёрнутом виде («0 вкладок»), слот-заглушки нет — целью дропа служит сама шапка.

Ключ `blattam-last-space` — последнее активное пространство: по умолчанию для save-пути (popup/горячая клавиша) и стартовое пространство view.

Ключ `blattam-lang` (chrome.storage.local) — язык интерфейса: 'ru' (по умолчанию, ключ отсутствует) или 'en'. Переключатель — «Настройки → Общие → Язык»; переключение перерисовывает без перезагрузки. Имена по умолчанию пространств/групп/вкладок создаются на текущем языке.

Ключ `blattam-folders` — **legacy**: потребляется только одноразовой миграцией (каждая папка любого уровня → отдельное пространство с тем же именем, вкладки переезжают folderId → spaceId, без папки → «Мои вкладки»). После миграции ключ удаляется.

Ключ `blattam-theme` (`chrome.storage.local`) — тема: `'light'` (по умолчанию) / `'dark'`.

Ключ `blattam-bg-image` (`chrome.storage.local`) — кастомная картинка-фон newtab-страницы: data URL (пусто/отсутствует — фон по умолчанию). Большой ключ (лимит ~4 МБ — по длине data URL при выборе файла) — только local, не sync.

Ключ `blattam-tab-color` (`chrome.storage.local`) — кастомный цвет карточек сохранённых вкладок: hex (например `#8a6d5c`); пусто/отсутствует — фон темы. Только local (как остальные per-device настройки).

Ключ `blattam-quick-search` (`chrome.storage.local`) — тумблер «Быстрый поиск» (экспериментальный режим): boolean, по умолчанию off (ключ отсутствует). Только local (per-device, как прочие настройки newtab-страницы).

Ключ `blattam-tabs` (список вкладок) — в **`chrome.storage.local`** (per-device, ~10 МБ — большие коллекции на 1000+ вкладок влезают; лимит sync 8 КБ/ключ ломал запись уже на ~20 вкладках). При загрузке — идемпотентная миграция: local пуст, а в sync непустой `blattam-tabs` → ключ копируется из sync в local и sync-ключ удаляется; local заполнен → только удаление stale-sync-ключа (local wins). Запускается и в background.js (до `loadTabs`/`saveTabs`), и в view.js (до первого рендера — без мигания). `blattam-spaces`, `blattam-groups`, `blattam-last-space` — в `chrome.storage.sync` (синк между устройствами; синк всей библиотеки — в будущем, вместе с фичей аккаунтов).

Ключ `blattam-trash` (`chrome.storage.local`) — корзина: массив записей = полный объект вкладки + `deletedAt` (мс). Per-device (как `blattam-tabs`). Удаление вкладок (✕ на карточке, массовое «✕ Удалить», Delete/Backspace) — БЕЗ confirm: вкладка уходит в корзину. Восстановление — кнопка «Корзина» в левой рейке (под «Настройками») открывает модалку #trash-modal: список (имя, url, дата удаления), «Вернуть» (одна) / «Удалить навсегда» (confirm) / «Вернуть все» / «Очистить корзину» (confirm); подпись кнопки рейки — счётчик «N в корзине».

## Ключевое поведение

- **Ctrl+T / кнопка «+»** — Chrome открывает новую вкладку → `view.html` (BlatTabs) автоматически через `chrome_url_overrides.newtab`.
- **Opera** — Opera не поддерживает `chrome_url_overrides.newtab` из манифеста (её new tab — фирменный startpage `chrome://startpage`), поэтому background.js перехватывает его runtime'ом: новая вкладка со startpage (URL `chrome://startpage` / `opera://startpage`, по `chrome.tabs.onCreated` / `onUpdated`) перенаправляется на `view.html`; при старте SW дополнительно сканируются открытые вкладки (Opera создаёт первую startpage-вкладку до регистрации слушателей). В Chrome это no-op (new tab уже открывает view.html через манифест). Встроенная вкладка «Speed Dial» (`chrome://startpage`) Opera не видима API расширений (нет в query, без событий) и её нельзя закрыть из расширения — окно открывается с вкладками [Speed Dial] + [BlatTabs], каждая новая вкладка (Ctrl+T / new-tab) становится BlatTabs.
- **Сохранить текущую вкладку** — из popup (с выбором пространства) или Ctrl+Shift+S. Сохранённые вкладки появляются мгновенно на всех открытых BlatTabs-страницах через `chrome.storage.onChanged`.
- **Пространства** — чипы в шапке (клик — переключение, активное подсвечено чернилом; высота чипа 26px); «+ Пространство» — модалка создания (пустое имя → «Пространство N», дубль пропускается); кнопка в правом краю ряда пространств (после чипов — чипы рендерятся первыми, кнопка последним элементом ряда), бледный текстовый стиль (без рамки); ✎/✕ в мета-строке (правее названия активного пространства + числа вкладок) — переименовать / удалить ТЕКУЩЕЕ (активное) пространство (кнопки статичны, активное пространство резолвится в момент клика; с confirm; вкладки удалённого пространства УДАЛЯЮТСЯ (каскодно), группы удаляются, `blattam-last-space` перенацелено); с чипа ✎/✕ убраны — чип чистая кнопка-переключатель. Чипы перетаскиваются на другие чипы — перестановка пространств, как drag карточек: захваченный чип исчезает из ряда (display:none), по ряду чипов за курсором идёт тёплая слот-заглушка `.space-ghost-slot` (высота чипа 26px, радиус чипа, фон `--ghost-bg` + пунктирный `--ghost-ring`) — единственный индикатор вставки (2px-линия на кромке цели убрана): левая половина целевого чипа — заглушка вставляется перед ним, правая — после; число элементов ряда при drag неизменно; дроп в любом месте ряда (зазор между чипами, отступы, кнопка «+ Пространство») ставит пространство в позицию заглушки (как у карточек — дроп в любом месте списка); no-op-guard: если порядок не изменился — запись в storage не идёт; порядок сохраняется в `blattam-spaces`; дроп на себя — no-op; активное пространство и `blattam-last-space` не меняются; ложный клик по чипу сразу после дропа не переключает пространство, настоящее нажатие — переключает
- **Группы** — сворачиваемые секции внутри пространства (клик по шапке — свернуть/развернуть, состояние в данных и переживает перерисовку); «+ Группа» — полноширинная пунктирная строка (40px, `1px dashed var(--dashed)`, hover `var(--hover)`/`var(--dashed-hover)`) в конце списка вкладок — во всех ветках рендера, включая полностью пустое пространство (пустое имя → «Группа N»); шапки групп перетаскиваются на другие шапки — reorder внутри активного пространства (верхняя половина цели — вставить перед, нижняя — after; 2px seam-индикатор `--gbar-seam` (бордовая, gradient-fade к краям) на кромке цели; порядок сохраняется в порядке `blattam-groups` — группы других пространств сохраняют относительный порядок, collapsed/члены остаются у группы, дроп на себя — no-op); счётчик групп в мета-строке больше не показывается; ✕ на шапке группы — удалить (вкладки удалённой группы удаляются — каскадно); ✎ на шапке группы (hover-only, рядом с ✕) — инлайн-ренейм: имя шапки становится `<input>` с текущим именем (Enter/blur — сохранить, Esc — отмена, пустое имя — старое имя сохраняется; клик не сворачивает группу и не стартует drag; запись в `blattam-groups`, дубли имён допустимы); ☑ на шапке группы (hover-only, при полностью выбранной группе — заполнен чернилом и видим без hover) — выбрать/снять выбор ВСЕХ вкладок группы (независимо от сворачивания): все уже выбраны → снять, иначе → добавить. Переезд вкладки в группу — через ghost-slot: мишень — карточки группы (заглушка встаёт в слот группы, place-tab задаёт groupId); шапка группы принимает карточку, когда у группы НЕТ ВИДИМЫХ карточек (пустая 0 вкладок, свёрнутая, единственная карточка перетаскивается): дроп на шапку = place-tab anchorIndex null (в конец списка) + groupId группы, карточка своей группы — NO-OP, армед-вид — тёплый тон (--ghost-bg/--ghost-ring); шапка группы С видимыми карточками — no-op, без подсветки; пустая группа рендерится в свёрнутом виде (раскрытие пустых групп убрано — клик по шапке no-op, `.group-empty-slot` не существует — шапка — единственная drop-цель); перенос в/из/внутри группы — только через ghost-slot; клик по шапке сразу после дропа (карточка/шапка — некоторые браузеры генерируют клик после drop) НЕ переключает сворачивание группы (окно 500 мс от последнего dragend) — дроп на свёрнутую группу уезжает в неё и АВТОМАТИЧЕСКИ РАЗВЁРТЫВАЕТ группу (вкладка видна; ложный post-drop клик не сворачивает обратно — см. ниже). ☑ у строки «Без группы» (hover, аналог ☑ шапки группы) — выбрать/снять ВСЕ негрупповые вкладки пространства (полный набор, независимо от поиска — скрытые фильтром тоже): все выделены → заполнен чернилом (виден без hover), повторный клик — снять всех. ⧉ на шапке группы (hover-only, в конце ряда контролов, после ✕; `.gopenall`, title «Открыть все вкладки группы») — открыть ВСЕ сохранённые вкладки группы (spaceId+groupId) в новых вкладках браузера тем же путём, что клик по карточке (per-tab `openUrl` → `open-one`); работает и у свёрнутой группы (шапка есть в обоих состояниях); пустая группа — no-op (кнопка остаётся); `stopPropagation` — клик не сворачивает группу; drag-safe через `guardDragOverButtons`.
- **Seam reorder групп (Toby 2.0)** — индикатор дропа при reorder групп (шапка на шапку) — 2px бордовая seam-линия из токена `--gbar-seam` (обе темы theme.css: light `rgba(107, 16, 32, 0.45)` / dark `rgba(230, 145, 160, 0.58)` — rgba, не hex) с gradient-fade к краям (прозрачно 0% и 100%, сплошная 8–92%) и opacity-переходом 90ms (была плоская 2px линия `var(--ink)`); классы `.drop-before`/`.drop-after` и селектор `.gbar.drop-before::before, .gbar.drop-after::after` без изменений.
- **Шапка группы: компактная в развёрнутом, полноширинная в свёрнутом** — шапка РАЗВЁРНУТОЙ группы — компактная левая «пилюля» ровно по шеврону сворачивания + имени группы + счётчику вкладок + hover-контролам (☑/✎/✕ — внутри компактной области) (`width: fit-content`, padding 2px 8px, margin-left 2px, border-radius 6px): hover-подсветка (`var(--gbar-hover)`) и клик-сворачивание действуют только на компактную область — клик в пустом месте справа от неё НЕ переключает группу. Шапка СВЁРНУТОЙ группы — без изменений: вся ширина строки (grid-column 1/-1, растянутая), подсветка hover и клик-разворачивание по любой точке строки. Класс `gbar-collapsed` ставится в `appendGroupBar` из `g.collapsed` (класс из данных группы при рендере, не мутация DOM); 1px-линия сверху (`::before`, `--gbar-top-line`) и reorder/drop-индикаторы — left:0/right:0 оверлеи — сужаются вместе с пилюлей. Drag/дроп-семантика без изменений: шапка остаётся drag-источником (reorder групп) и drop-целью (gbar→gbar reorder; карточка→gbar при отсутствии видимых карточек группы), заглушка карточки над шапкой и guard-кнопки сохранены.
- **Тон шапки группы при перетаскивании карточки (drag-state hover tone)** — во время перетаскивания карточки (`body.dragging-card`, ставится/снимается в `beginCardDrag`/`endCardDrag` — единственная точка для обоих путей: HTML5 dragstart/dragend и pointer-путь) hover шапки СВЁРНУТОЙ группы (`.gbar.gbar-collapsed`, полноширинная строка) — тёплый акцент `var(--ghost-bg)` (тот же токен, что у заглушки: light `#fbe3b6` / dark `#4c3c22` — только токены, без hex), а hover шапки РАЗВЁРНУТОЙ группы (компактная «пилюля») тон не меняет (база — прозрачная, `--gbar-hover` не проявляется). Вне драга hover без изменений в обеих темах (и развёрнутая, и свёрнутая — `var(--gbar-hover)`). Тесты: TestDragGbarHoverTone (4).
- **DnD: post-drop клик не раскрывает группу** — дроп карточки на шапку свёрнутой/пустой группы уносит её в группу; ложный `click`, который браузер генерирует после drop, не сворачивает/раскрывает группу — даже когда перерисовка медленная (большая коллекция, соседние группы раскрыты) и клик приходит за 500ms-окном после `dragend` (one-shot флаг `pendingGbarClickAfterDrag`, вооружается на dragstart карточки и на drop по шапке — клик гасится, когда приходит и ДО dragend, и после; сбрасывается новым `mousedown` — реальные клики не глотаются; дроп по шапке также снимает тёплую заглушку ghost-slot, а отложенная заглушка не вставляется для отсоединённой карточки).
- **Дроп вкладки в свёрнутую группу — авто-развёртывание** — любой дроп, который уносит вкладку в СВЁРНУТУЮ группу, разворачивает её, чтобы вставленная вкладка была видна (view.js `expandGroupForDrop`: `collapsed=false` + запись `blattam-groups` → onChanged → перерисовка; no-op, если группа уже развёрнута). Пути: карточка на шапку свёрнутой группы (HTML5-дроп + pointer-путь), выделенный батч (place-tabs), вкладка правой рейки на шапку группы (`saveBtToGroup`) и в секцию свёрнутой группы (ghost-слот, `saveBtToCenter`/`place-tab`). Дроп-семантика и one-shot-подавление ложного post-drop клика без изменений — группа разворачивается дропом и НЕ сворачивается ложным кликом (тесты: TestCollapsedGroupDropExpand 5 + обновлённые TestGroupBarDrop/TestPostDropClick*/TestDragGhostOverCollapsed).
- **Переезд между пространствами** — drag&drop карточки на чип пространства (groupId очищается — между пространствами группы не ездят).
- **Поиск** — фильтрация по имени, заголовку и URL прямо на странице — поле наверху левой рейки (полная ширина рейки; ≤760px — скрыто, иконная рейка); клавиша `/` фокусирует поле. URL на карточке не отображается, но ищется. «Ничего не найдено» показывается только при активном поиске — сворачивание групп (карточек нет, но поиска нет) его больше не триггерит.
- **Быстрый поиск (экспериментальный режим)** — тумблер в настройках (раздел «Экспериментальное» после «Языка», `#qs-toggle` → `blattam-quick-search`, дефолт off). Включён — на newtab-странице любая буква (латиница/кириллица, с Shift или без) БЕЗ клика по строке дописывает её в `#search` и сразу фильтрует карточки (тот же фильтр, case-insensitive); на каждое нажатие — вспышка: потемнение окна (`#qs-overlay`, `.qs-overlay`, z-index 500 — ниже оверлея модалки) + большая буква 200px (тонкая, font-weight 300) в центре (`#qs-letter`), fade 650ms ease-out, новая буква перезапускает вспышку; цифры/символы не работают; Backspace — удалить последнюю букву (только на непустом запросе — на пустом старое поведение), Escape — сброс (существующий) + мгновенное скрытие оверлея; в фокусе любого поля ввода или при открытой модалке буквы не перехватываются; выключение тумблера гасит оверлей. Захват фокуса: при включённом режиме при загрузке страницы запускается `initFocusGrab` (сразу + 250/700 мс) — `grabPageFocus` возвращает фокус в страницу, если после Ctrl+T / «+» Chrome держит его в адресной строке (без этого первая буква ушла бы в омнибокс); при выключённом режиме захват не запускается. - **Drag & drop (reorder): ghost-slot (заглушка слота)** — при захвате карточки на её месте в сетке появляется ghost-заглушка того же размера и скругления (тёплый тон: фон `var(--ghost-bg)`, пунктирная граница `var(--ghost-ring)`; пустая, не draggable, прозрачная для курсора — `pointer-events:none`); заглушка следует за мышью в потенциальный слот вставки с учётом секций (начало/середина/конец группы, конец списка — на границе секций по позиции курсора относительно середины шапки группы: выше середины — конец предыдущей группы, ниже — начало текущей; заглушка якорится ПОСЛЕДНЕЙ карточкой предыдущей секции (никогда «перед» шапкой следующей: при прогоне свёрнутых групп между секциями заглушка не встаёт в пространство низкой свёрнутой группы — она не «раскрывается» с призрачной вкладкой); соседние карточки сдвигаются естественным reflow сетки), нативный drag-образ браузера следует за курсором (клон-призрака нет); при отпускании вкладка заменяет заглушку и встаёт в позицию её слота в полном 'blattam-tabs', а если заглушка в другой группе — вкладка переезжает в ту группу (groupId обновляется; негрупповая секция — groupId становится null); дроп на чип пространства — move-поведение без изменений; дроп на шапку группы с видимыми карточками — no-op; на шапку пустой/свёрнутой группы и на слот-заглушку пустой группы («Перетащите вкладку сюда») — вкладка в группу (place-tab, anchorIndex null — в конец списка; своя группа — no-op), над чипом пространства заглушка замирает (над шапкой/слотом — прячется целиком, см. «Drag-layout» ниже); заглушка убирается на dragend; drag без drop — карточка возвращается в свой слот, заглушка убирается, storage не тронут; перерисовка (storage.onChanged) во время drag — заглушка убирается аккуратно. Число строк: схваченная карточка выдёргивается из сетки (inline display:none), и ghost-slot того же размера занимает её клетку (сразу после карточки) — пока заглушка в исходной секции, число строк секции не меняется и список под ней не сдвигается; когда заглушка уходит в другую секцию, карточки закрывают высвобожденный слот естественным reflow без «дырки»; последняя строка, которая бы схлопнулась (секция теряет ряд видимых карточек, например группа с одной вкладкой), ДЕРЖИТСЯ невидимой заглушкой-холдером `.tab-row-keeper` (см. «Drag-layout: строка исходной секции не схлопывается» ниже) — шапка группы при этом остаётся вооружённой целью дропа (groupVisibleCardCount); на dragend/Escape карточка возвращается в свой слот без следов.
- **Драг: курсор-ориентированный слот, touch-rule (карточка под курсором)** — заглушка занимает место конкретной карточки, прямо под курсором (любая точка в пределах её rect), а не абстрактную середину ряда: сдвиг несхваченных карточек происходит ТОЛЬКО в момент касания курсором карточки (входа в её rect), и работает с обеих сторон — при касании заглушка перескакивает на противоположную (по DOM) сторону наведённой карточки: карточка уезжает в сторону, ОТ которой пришёл курсор, и освобождает свою прежнюю клетку (заглушка встаёт в неё) — при подходе СЛЕВА карточка уезжает влево и заглушка — в её прежнюю клетку (было: сдвиг происходил в зазоре ДО касания и заглушка оставалась на ячейку позади — сломано), при подходе СПРАВА — вправо; внутри карточки якорь заморожен (без сдвига); в зазоре между карточками на СВОЕЙ строке заглушки — sticky (ничего не двигается до следующего касания); курсор над пустым местом: пустые правые ячейки незаполненной строки — конец ряда (остаётся досягаемым), зазор на другой строке или заглушки нет — legacy-fallback по счётчику «пройдённых» карточек (ниже низа или справа от центра) — начало/конец секции и следование заглушки между строками сохранены. view.js: `cursorCardAnchor(clientX, clientY)` — CARD-путь (dragSourceUrl заполнен, без dragSourceGroupId) и рейка→центр (см. буллет «Драг рейки → центр: та же территория»); чипы — через slotAnchor(cardGapIndex(...)) без изменений; touch-состояние `pdLastTouchCard`/`pdLastTouchAnchor` (сброс в dragstart/endCardDrag — freeze внутри карточки опирается на TOUCH-якорь, а не на pdLastAnchor: промежуточные gap/sticky-якоря перезаписывают pdLastAnchor и ломают freeze при возврате курсора в ту же карточку). placeCardToSlot умеет средний «after»-якорь (вставка ПОСЛЕ якорной карточки в порядке секции). Семантика дропа — вставка в слот заглушки по полному 'blattam-tabs' + groupId. Тесты: TestCursorOrientedMove (7, перецелен на touch-rule) + TestTouchOrientedMove (10: HTML5 — стабильность якоря в карточке / касание вправо-влево / sticky в зазоре / конец незаполненной строки / cross-row legacy / дроп с обеих сторон, обе темы; real mouse — рефлоу ровно в момент касания при движении вправо и влево, sticky в зазоре, коммит дропа в позиции заглушки).
- **Драг: территории (midpoint-расщепление зазоров, подход по сторонам, хвосты секций)** — «ничья земля» между карточками убрана: территория карточки = её rect + половины соседних зазоров (midpoint-расщепление — горизонтально в строке и вертикально по границам строк/секций); курсор в территории карточки — она становится владельцем и сдвигается (FLIP-слайд): заглушка занимает её старую клетку, владелец уезжает туда, откуда пришёл драг. Сторона подхода: слева/сверху от карточки → заглушка 'after' (владелец уезжает раньше в DOM), справа/снизу → 'before' (владелец уезжает позже); внутри территории того же владельца якорь заморожен (в горизонтальном подходе — по владельцу+стороне: пересечение на противоположную сторону переворачивает сторону и ре-коммитит; в вертикальных зонах — только по владельцу, без рефлоу). Заглушка — элемент ряда: её клетка (домашняя позиция) — собственная sticky-территория (якорь = текущее DOM-положение, дроп домой — no-op). Хвост секции: вся зона ниже последней строки карточек (до шапки следующей секции или низа списка) — территория хвоста: заглушка видна, владелец — последняя карточка последней строки (подход снизу → 'before'), дроп — коммит. Единственная оставшаяся «ничья земля» — полоса у низа всего списка (ниже последней группы) — дроп там отменяет (вкладка домой, storage не тронут). view.js: `cursorCardAnchor` (строки/секции из видимых карточек + заглушки как элемента ряда, `ownerOf` — midpoint-тайлинг, `commitOwner(owner, side, flip)`, `betweenSections` — midpoint-расщепление межсекционного зазора), `cardAreaEmptyBand` — только нижняя полоса. Тесты: TestTouchOrientedMove (cross-row midpoint / intersection выше midpoint), TestDragGhostOverCollapsed (хвост над свёрнутой шапкой/группой), TestDragSourceRowHold (хвост ниже последней строки)
- **FLIP-иммунная геометрия территорий (layout-rect)** — осцилляция курсора между соседними вкладками во время FLIP-слайда больше не дёргает механизм: во время 200ms-слайда `getBoundingClientRect()` сдвигающихся карточек отдаёт mid-flight (transformed) позиции, и территории, посчитанные по этим live-rects, давали сдвинутые на полуклетки midpoint-границы — событие во время слайда резолвило WRONG-owner и freeze защёлкивал чужой anchor (заглушка прыгала/отставала/застревала; чем больше возишь курсор, тем хуже). Теперь `cursorCardAnchor` считает территории по `layoutRect(el)` — rect минус in-flight transform (то же вычитание матрицы `getComputedStyle`, что и `applyFlipFrom`): строки/секции по rect.top, midpoint-тайлинг ряда, touch-rect, A3a-конец ряда и шапные границы — всё в layout-координатах (ghost-slot/шапки/#tabs-list transform не имеют — no-op). Якорь детерминирован относительно DOM-порядка + grid-layout независимо от состояния анимации; freeze (pdLastTouchCard/pdLastTouchAnchor) ведёт себя как задумано — рефлоу только на границах settled-территорий. Тесты: TestTerritoryOscillation (3, pointer-путь, реальная мышь: mid-FLIP wrong-owner-коммит / непрерывная осцилляция — settled-позиция заглушки / settled-пересечения — точные позиции после каждого)
- **Драг: без «дерганья вниз» при проносе мимо полной строки группы (row-keeper до post-снимка FLIP)** — заглушка уезжает из исходной секции и та теряет строку (nFull ≡ 1 mod cols): невидимый холдер `.tab-row-keeper` вставлялся ПОСЛЕ post-снимка FLIP — post-rects считались на схлопнутом layout и старт-трансформ = +высота строки: все карточки ниже исходной секции на кадр уезжали вниз и 200ms-слайдом возвращались. Теперь `syncSourceRowKeeper()` в list-ветке `trackCardDragAt` вызывается между `moveGhostSlot` и `applyFlipFrom` (post-геометрия FLIP видит layout с холдером). Тесты: TestFullRowGroupSweep (5, pointer-путь, mid-slide сэмплинг 30/60/120ms)
- **Драг: без «дерганья вниз» в зазоре между полной строкой группы и шапкой следующей группы (снимок FLIP до рефлоу)** — та же порода в зазоре G↔H (курсор касается пространства между последней вкладкой полной группы G и шапкой группы H): `updateWrapHiddenCard` (restore крайней карточки G при уходе заглушки из неё) выполнялся ДО снимка FLIP — «first»-снимок фиксировал фантомную раскладку (5 карточек + заглушка = +1 строка, на экран не выводилась), и старт-трансформ = +высота строки: последняя карточка G, шапка H и всё ниже на 200ms уезжали вниз и возвращались слайдом. Теперь снимок FLIP в `trackCardDragAt` берётся ПЕРЕД всеми рефлоу события (wrap-hidden, ход заглушки, холдер): «first» = истинное до-состояние, «last» = финальный layout. Тесты: TestFullRowGapJerk (5, pointer-путь, вертикальный пронос + chase, mid-slide raw-top)
- **Drag-layout: рефлоу слота и заглушка скрыта ЦЕЛИКОМ над шапкой/слотом** — при захвате карточки и уходе заглушки от её слота соседние карточки ЗАКРЫВАЮТ высвобожденный слот естественным reflow сетки (пустой «дыры» на месте карточки нет); число строк исходной секции при этом фиксировано: его держит сама заглушка, занимающая клетку выдернутой карточки — группы/вкладки под секцией не сдвигаются во время быстрого драга (последняя строка, которая бы схлопнулась, держится невидимой заглушкой-холдером `.tab-row-keeper` — см. «Drag-layout: строка исходной секции не схлопывается» ниже). Над шапкой ЛЮБОЙ группы (`.gbar` — развёрнутую, свёрнутую или пустую) и над слотом пустой группы (`.group-empty-slot`) заглушка прячется ЦЕЛИКОМ (`display:none` — её ячейка сетки освобождается: ни «тёплая» заглушка на старом месте, ни «дырки» — сетка перетекает), освобождённая ячейка заглушки закрывается reflow (число строк не меняется, пока в секции хватает карточек); заглушка остаётся в DOM и ВЕРНУЕТСЯ (display:''), когда курсор снова попадает в список (честный слот вставки). Пустые полосы карточной сетки — всех секций: (A) ЦЕЛАЯ строка шапки секции — от её верха (.gbar / .loose-label / верх списка) до верха её первой видимой строки (включая ПУСТУЮ часть шапковой строки развёрнутой группы — справа от компактной «пилюли» .gbar); (B) между низом последней видимой строки и верхом шапки следующей секции; у последней секции — до НИЗА списка (строка #add-group-btn и нижний отступ 110px — тоже полоса); (C) вертикальный зазор сетки (row-gap) между двумя строками карточек внутри секции — заглушка прячется целиком (display:none, как над шапкой): строки исходной секции держит условный row-keeper, а дроп в полосу — отмена (вкладка возвращается в исходный слот, без записи в storage и без reorder, оба пути драга: HTML5 и pointer). Не полосы (поведение не меняется): над .tab-card, над самой .gbar (дроп — в группу), над .group-empty-slot, пустые ячейки своей строки незаполненного ряда (заглушка видима в потенциальном слоте), чипы пространств, правая рейка, #spaces-bar. Над чипом пространства заглушка, как и раньше, замирает. Семантика дропа: дроп в пустую полосу — отмена (вкладка возвращается в исходный слот, storage не меняется), дроп на шапку пустой/свёрнутой группы — вкладка в группу (place-tab, anchorIndex null), группа разворачивается (post-drop-клик подавлен — не сворачивает обратно), дроп на шапку с видимыми карточками — no-op.
- **Drag: единственный вкладка/вкладка «одна в группе» — домашний слот, дроп домой no-op** — когда в группе ровно одна вкладка (или единственная негрупповая), во время драга секция читается «пустой» (карточка скрыта) и геометрия прыгала через её полосу в соседнюю секцию: в момент захвата заглушка уезжала в соседнюю группу, а дроп домой менял группу/позицию — вкладку было невозможно вернуть на место. Теперь: пока курсор в полосе исходной секции (от низа её шапки до верха шапки следующей), заглушка остаётся в слоте схваченной карточки (домой, видима, не уезжает), а вкладку «несёт» нативный drag-образ браузера; дроп домой — точный no-op (позиция в 'blattam-tabs' и groupId не меняются). Механизм (view.js): `slotIsSourceHome(clientY)` в `slotAnchor` (домашний якорь `{el: dragSourceCardEl, side:'after'}`) + guard в `placeCardToSlot` (якорь — сама исходная карточка, сторона «после» → no-op). Шапка/слот СВОЕЙ группы, multi-tab-секции и дроп в другую группу — без изменений (TestOnlyTabHomeDrop).
- **Перенос выделенного батча** — перетащил карточку, входящую в выделение (чекбоксы, >1 вкладки), — уезжают ВСЕ выделенные вкладки: в рендере — как перенос одной вкладки (скрывается только захваченная карточка, заглушка одна, клон-призрака нет); батч встаёт блоком на позицию слота в исходном порядке вкладок (`place-tabs` в background: вырезка из полного массива 'blattam-tabs', вставка перед/после якорной вкладки или в конец; группа — группа целевой секции, пространство не меняется); на шапку/слот пустой/свёрнутой группы — батч целиком в группу (если хотя бы одна вкладка не там), на чип пространства — каждая вкладка батча переезжает в пространство (группы очищаются); если порядок и группы не меняются (якорь — член батча) — no-op, сообщение не шлётся; не-выделенная карточка уезжает одна (place-tab).

- **Drag чипа пространства: плавное перемещение (pointer-путь)** — в реальном Chrome перетаскивание чипа пространства работает по той же механике, что и драг карточки: движение больше 8 px от захвата — оригинал исчезает из ряда (тёплая `.space-ghost-slot` в его месте, создаётся синхронно при захвате), под курсором клон чипа (`.pd-clone`, `position:fixed`, scale 1.02 + тень) 1:1, ghost-slot ходит по ряду (до/после чипа по половине, FLIP-слайд соседей 200 ms; над самим рядом — держит DOM-позицию), отпускание — синхронный коммит (над чипом — reorder по половине, над зазором ряда/«+ Пространство» — текущая позиция заглушки, в остальном — отмена без записи), клон «приземляется» в цель за 180 ms (fade + scale 0.96); Escape или отпускание вне ряда — отмена; дроп в собственный слот — no-op (без записи); обычный клик (без движения) по-прежнему переключает пространство; путь карточка→чип (перенос вкладки в space) и заморозка заглушки над чипом не тронуты; чип-путь переиспользует хелперы карточного пути (`pdCreateClone`/`pdFinishClone`/`applyFlipFrom`, обобщённый `snapshotCardRects`) при своём состоянии `pcd`; gbar и рейка получили isTrusted-guard в dragstart (срабатывают, когда их pointer-путь в следующих волнах обрабатывает press — флаги gbarPointerPress/railPointerPress на pointerdown, — или чужой pointer-драг карточки/чипа пересекает элемент: pdForeignActive; trusted dragstart гасится и не крадёт drag-source) — реальные HTML5-драги пока не затронуты, синтетический путь харнесса без изменений

## Сообщения между компонентами

| Действие | Откуда → Куда | Описание |
|---|---|---|
| `save-current` | popup/hotkey → background | Сохранить текущую активную вкладку (spaceId → по умолчанию) |
| `add-tab` | view/popup → background | Создать запись вручную (имя + URL) |
| `open` / `delete` | popup/view → background | Открыть/удалить вкладку по индексу |
| `open-one` / `open-many` | view → background | Открыть одну / несколько вкладок (пачкой — без активации) |
| `move-tab` | view → background | Перемещение: spaceId (в другое пространство, groupId очищается) и/или groupId (null — «Без группы») |
| `rename-tab` / `reorder-tab` | view → background | Переименование / reorder |
| `update-tab` | view → background | Редактирование вкладки: имя/адрес/комментарий (пустые имя/адрес → старые значения, пустой комментарий → удалить ключ) |
| `place-tab` | view → background | Дроп вкладки в позицию ghost-слота: позиция по якорю (перед/после вкладки; конец секции — после последней вкладки этой секции) + groupId секции заглушки (null — «Без группы»); тот же слот и та же группа — no-op; `anchorIndex: null` — в конец списка (дроп на шапку/слот пустой или свёрнутой группы) |
| `create-space` / `delete-space` / `rename-space` | view/popup → background | CRUD пространств |
| `create-group` / `delete-group` | view → background | CRUD групп (удаление: вкладки остаются в пространстве) |

**Автообновление view/popup:** `chrome.storage.onChanged` — все открытые newtab-страницы и popup реагируют на изменения storage без сообщений (popup дополнительно синхронизирует выбранное пространство с `blattam-last-space` и подсвечивает только что созданное пространство).

## Загрузка и установка расширения

1. Открыть `chrome://extensions`.
2. Включить **«Режим разработчика»** (правый верхний угол).

- **Device Flow: поллинг message-driven со страницы newtab** — MV3 service worker умирает через ~30 с простоя, а рекурсивный setTimeout-поллинг в SW мёртв (пользователю нужно 30–90 с на ввод кода на github.com/login/device): страница view.js шлёт `device-flow-poll` каждые N с — каждое сообщение будит SW, он делает один шаг поллинга; состояние — в storage `github-device-flow` (device_code/user_code/interval/expires_at), успех/ошибка — в ответе (токен → storage → refreshAccount); страховка при закрытой странице — alarm `blattam-device-poll` (30 с, manifest: +alarms); disconnect очищает состояние + аларм
- **Device Flow: slow_down + reuse кода + verify-фолбэк** — лимит GitHub (`slow_down`) ставит паузу на interval из ответа (`slow_down_until` в состоянии `github-device-flow`; поллинг страницы и аларм не делают fetch до конца паузы, `authorization_pending` её снимает); повторный клик переиспользует активный неистёкший device code (новый код — только когда состояния нет/истекло); все запросы к api.github.com — 3 попытки (`fetchGitHub`; каждая попытка ограничена 10 с — AbortController, иначе verify вёл карточку ~минуту; из сети пользователя API нестабилен — 1 из 2 IP «чёрный»); при неудачной verify и существующем токене карточка показывает кэшированный логин (`blattam-github-login`), без кэша — «Подключено · проверяем аккаунт…» (токен действителен, недоступен только API), а не «не подключён»

- **GitHub-модалка: мгновенный статус + реальные ошибки синка + самовосстановление gist** — (1) при токене статус «Подключено · проверяем аккаунт…» виден МГНОВЕННО при открытии модалки (до ответа verify-github) — не «Не подключён» при видимой «Отключить»; рейка при токене + кэше логина сразу показывает кэшированный логин (до verify). (2) ошибка синхронизации видна в UI с причиной: «Ошибка синхронизации: network» / «Ошибка синхронизации: api 404» / «…: bad-payload» / «…: no-token» (i18n `account_sync_error_detail`, {err} — машиночитаемые значения из background: sync-now возвращает {pulled, pushed, error}); при ошибке статус не затирается перерисовкой модалки (3-секундный renderGitHubModal — только при успехе). (3) мёртвый gist (удалён / создан другим аккаунтом): PUT → 404 → blattam-gist-id снимается и gist пересоздаётся одним POST (новый id сохраняется); GET 404 (pull) — не ошибка.
