# BlatTabs — расширение для управления сохранёнными вкладками

Браузерное расширение Chrome (Manifest V3), менеджер сохранённых вкладок, вдохновлённый toby.io / Taby. Заменяет страницу новой вкладки на свою — при Ctrl+T или клике по «+» в браузере открывается BlatTabs с сохранёнными вкладками.

## Архитектура

```
manifest.json          — Manifest V3, chrome_url_overrides.newtab → view.html
background.js          — Service worker: CRUD вкладок/пространств/групп, миграция legacy-папок
popup.html / popup.js  — Popup: «Сохранить вкладку» с выбором пространства
view.html / view.js    — Страница новой вкладки (newtab override): пространства, группы, карточки
theme.css              — дизайн-токены (CSS-переменные), общие для view и popup
icons/                 — иконки расширения: icon16.png / icon48.png / icon128.png
build_zip.py           — сборка dist/BlatTabs-v<версия>.zip для Chrome Web Store (только stdlib)
store/                 — материалы магазина: DESCRIPTION.md + 3 PNG-макета
```

### Хранилище

Ключ `blattam-tabs`, элементы формата:
```js
{ name, url, title?, favIconUrl?, comment?, spaceId (обязательно), groupId? }
```
`favIconUrl` — URL фавикона сайта (ставится при сохранении через popup/hotkey, если у вкладки он есть; data: URL тоже допустим; без него — поле отсутствует, в view отрендерится буквенный fallback). `groupId` — группа внутри пространства (отсутствует/null — вкладка вне групп). `comment` — свободный комментарий к вкладке: показывается внизу внутри карточки (моно, обрезается); пустой/отсутствующий — поле не ставится (из записи уходит сам ключ).

Ключ `blattam-spaces` — пространства (плоские, без вложенности):
```js
{ id, name }
```
Первое по умолчанию — «Мои вкладки». Дубли по имени (без учёта регистра) не создаются.

Ключ `blattam-groups` — сворачиваемые группы внутри пространств:
```js
{ id, name, spaceId, collapsed }
```
Группы плоские, живут в одном пространстве. Пустая группа рендерится с «0 вкладок». Группа, потерявшая последнюю вкладку, автоматически сворачивается (collapsed: true — шапка с «0 вкладок», без строки «Перетащите вкладку сюда»); свежесозданная или вручную развёрнутая пустая группа остаётся развёрнутой — её слот-заглушка — цель дропа.

Ключ `blattam-last-space` — последнее активное пространство: по умолчанию для save-пути (popup/горячая клавиша) и стартовое пространство view.

Ключ `blattam-folders` — **legacy**: потребляется только одноразовой миграцией (каждая папка любого уровня → отдельное пространство с тем же именем, вкладки переезжают folderId → spaceId, без папки → «Мои вкладки»). После миграции ключ удаляется.

Ключ `blattam-theme` (`chrome.storage.local`) — тема: `'light'` (по умолчанию) / `'dark'`.

Ключ `blattam-bg-image` (`chrome.storage.local`) — кастомная картинка-фон newtab-страницы: data URL (пусто/отсутствует — фон по умолчанию). Большой ключ (лимит ~4 МБ — по длине data URL при выборе файла) — только local, не sync.

Ключ `blattam-tab-color` (`chrome.storage.local`) — кастомный цвет карточек сохранённых вкладок: hex (например `#8a6d5c`); пусто/отсутствует — фон темы. Только local (как остальные per-device настройки).

Ключ `blattam-tabs` (список вкладок) — в **`chrome.storage.local`** (per-device, ~10 МБ — большие коллекции на 1000+ вкладок влезают; лимит sync 8 КБ/ключ ломал запись уже на ~20 вкладках). При загрузке — идемпотентная миграция: local пуст, а в sync непустой `blattam-tabs` → ключ копируется из sync в local и sync-ключ удаляется; local заполнен → только удаление stale-sync-ключа (local wins). Запускается и в background.js (до `loadTabs`/`saveTabs`), и в view.js (до первого рендера — без мигания). `blattam-spaces`, `blattam-groups`, `blattam-last-space` — в `chrome.storage.sync` (синк между устройствами; синк всей библиотеки — в будущем, вместе с фичей аккаунтов).

## Ключевое поведение

- **Ctrl+T / кнопка «+»** — Chrome открывает новую вкладку → `view.html` (BlatTabs) автоматически через `chrome_url_overrides.newtab`.
- **Сохранить текущую вкладку** — из popup (с выбором пространства) или Ctrl+Shift+S. Сохранённые вкладки появляются мгновенно на всех открытых BlatTabs-страницах через `chrome.storage.onChanged`.
- **Пространства** — чипы в шапке (клик — переключение, активное подсвечено чернилом; высота чипа 26px); «+ Пространство» — модалка создания (пустое имя → «Пространство N», дубль пропускается); кнопка в правом краю ряда пространств (после чипов — чипы рендерятся первыми, кнопка последним элементом ряда), бледный текстовый стиль (без рамки); ✎/✕ на чипе (hover) — переименовать / удалить (с confirm; вкладки удалённого пространства уходят в первое оставшееся, группы удаляются, `blattam-last-space` перенацелено). Чипы перетаскиваются на другие чипы — перестановка пространств, как drag карточек: захваченный чип исчезает из ряда (display:none), по ряду чипов за курсором идёт тёплая слот-заглушка `.space-ghost-slot` (высота чипа 26px, радиус чипа, фон `--ghost-bg` + пунктирный `--ghost-ring`) — единственный индикатор вставки (2px-линия на кромке цели убрана): левая половина целевого чипа — заглушка вставляется перед ним, правая — после; число элементов ряда при drag неизменно; дроп в любом месте ряда (зазор между чипами, отступы, кнопка «+ Пространство») ставит пространство в позицию заглушки (как у карточек — дроп в любом месте списка); no-op-guard: если порядок не изменился — запись в storage не идёт; порядок сохраняется в `blattam-spaces`; дроп на себя — no-op; активное пространство и `blattam-last-space` не меняются; ложный клик по чипу сразу после дропа не переключает пространство, настоящее нажатие — переключает
- **Группы** — сворачиваемые секции внутри пространства (клик по шапке — свернуть/развернуть, состояние в данных и переживает перерисовку); «+ Группа» — полноширинная пунктирная строка (40px, `1px dashed var(--dashed)`, hover `var(--hover)`/`var(--dashed-hover)`) в конце списка вкладок — во всех ветках рендера, включая полностью пустое пространство (пустое имя → «Группа N»); шапки групп перетаскиваются на другие шапки — reorder внутри активного пространства (верхняя половина цели — вставить перед, нижняя — after; 2px-индикаторная линия `var(--ink)` на кромке цели; порядок сохраняется в порядке `blattam-groups` — группы других пространств сохраняют относительный порядок, collapsed/члены остаются у группы, дроп на себя — no-op); счётчик групп в мета-строке больше не показывается; ✕ на шапке группы — удалить (вкладки остаются в пространстве); ✎ на шапке группы (hover-only, рядом с ✕) — инлайн-ренейм: имя шапки становится `<input>` с текущим именем (Enter/blur — сохранить, Esc — отмена, пустое имя — старое имя сохраняется; клик не сворачивает группу и не стартует drag; запись в `blattam-groups`, дубли имён допустимы); ☑ на шапке группы (hover-only, при полностью выбранной группе — заполнен чернилом и видим без hover) — выбрать/снять выбор ВСЕХ вкладок группы (независимо от сворачивания): все уже выбраны → снять, иначе → добавить. Переезд вкладки в группу — через ghost-slot: мишень — карточки группы (заглушка встаёт в слот группы, place-tab задаёт groupId); шапка группы принимает карточку, когда у группы НЕТ ВИДИМЫХ карточек (пустая 0 вкладок, свёрнутая, единственная карточка перетаскивается): дроп на шапку = place-tab anchorIndex null (в конец списка) + groupId группы, карточка своей группы — NO-OP, армед-вид — тёплый тон (--ghost-bg/--ghost-ring); шапка группы С видимыми карточками — no-op, без подсветки; пустая развёрнутая группа рендерит под шапкой полноширинный пунктирный слот-заглушку «Перетащите вкладку сюда» (.group-empty-slot, высота карточки 80px, 1px dashed --dashed, --card-radius, --text-faint, --font-mono) — он тоже drop-цель; перенос в/из/внутри группы — только через ghost-slot; клик по шапке сразу после дропа (карточка/шапка — некоторые браузеры генерируют клик после drop) НЕ переключает сворачивание группы (окно 500 мс от последнего dragend) — дроп на свёрнутую группу уезжает в неё и АВТОМАТИЧЕСКИ РАЗВЁРТЫВАЕТ группу (вкладка видна; ложный post-drop клик не сворачивает обратно — см. ниже). ☑ у строки «Без группы» (hover, аналог ☑ шапки группы) — выбрать/снять ВСЕ негрупповые вкладки пространства (полный набор, независимо от поиска — скрытые фильтром тоже): все выделены → заполнен чернилом (виден без hover), повторный клик — снять всех. ⧉ на шапке группы (hover-only, в конце ряда контролов, после ✕; `.gopenall`, title «Открыть все вкладки группы») — открыть ВСЕ сохранённые вкладки группы (spaceId+groupId) в новых вкладках браузера тем же путём, что клик по карточке (per-tab `openUrl` → `open-one`); работает и у свёрнутой группы (шапка есть в обоих состояниях); пустая группа — no-op (кнопка остаётся); `stopPropagation` — клик не сворачивает группу; drag-safe через `guardDragOverButtons`.
- **Шапка группы: компактная в развёрнутом, полноширинная в свёрнутом** — шапка РАЗВЁРНУТОЙ группы — компактная левая «пилюля» ровно по шеврону сворачивания + имени группы + счётчику вкладок + hover-контролам (☑/✎/✕ — внутри компактной области) (`width: fit-content`, padding 2px 8px, margin-left 2px, border-radius 6px): hover-подсветка (`var(--gbar-hover)`) и клик-сворачивание действуют только на компактную область — клик в пустом месте справа от неё НЕ переключает группу. Шапка СВЁРНУТОЙ группы — без изменений: вся ширина строки (grid-column 1/-1, растянутая), подсветка hover и клик-разворачивание по любой точке строки. Класс `gbar-collapsed` ставится в `appendGroupBar` из `g.collapsed` (класс из данных группы при рендере, не мутация DOM); 1px-линия сверху (`::before`, `--gbar-top-line`) и reorder/drop-индикаторы — left:0/right:0 оверлеи — сужаются вместе с пилюлей. Drag/дроп-семантика без изменений: шапка остаётся drag-источником (reorder групп) и drop-целью (gbar→gbar reorder; карточка→gbar при отсутствии видимых карточек группы), заглушка карточки над шапкой и guard-кнопки сохранены.
- **Тон шапки группы при перетаскивании карточки (drag-state hover tone)** — во время перетаскивания карточки (`body.dragging-card`, ставится/снимается в `beginCardDrag`/`endCardDrag` — единственная точка для обоих путей: HTML5 dragstart/dragend и pointer-путь) hover шапки СВЁРНУТОЙ группы (`.gbar.gbar-collapsed`, полноширинная строка) — тёплый акцент `var(--ghost-bg)` (тот же токен, что у заглушки: light `#fbe3b6` / dark `#4c3c22` — только токены, без hex), а hover шапки РАЗВЁРНУТОЙ группы (компактная «пилюля») тон не меняет (база — прозрачная, `--gbar-hover` не проявляется). Вне драга hover без изменений в обеих темах (и развёрнутая, и свёрнутая — `var(--gbar-hover)`). Тесты: TestDragGbarHoverTone (4).
- **DnD: post-drop клик не раскрывает группу** — дроп карточки на шапку свёрнутой/пустой группы уносит её в группу; ложный `click`, который браузер генерирует после drop, не сворачивает/раскрывает группу — даже когда перерисовка медленная (большая коллекция, соседние группы раскрыты) и клик приходит за 500ms-окном после `dragend` (one-shot флаг `pendingGbarClickAfterDrag`, вооружается на dragstart карточки и на drop по шапке — клик гасится, когда приходит и ДО dragend, и после; сбрасывается новым `mousedown` — реальные клики не глотаются; дроп по шапке также снимает тёплую заглушку ghost-slot, а отложенная заглушка не вставляется для отсоединённой карточки).
- **Дроп вкладки в свёрнутую группу — авто-развёртывание** — любой дроп, который уносит вкладку в СВЁРНУТУЮ группу, разворачивает её, чтобы вставленная вкладка была видна (view.js `expandGroupForDrop`: `collapsed=false` + запись `blattam-groups` → onChanged → перерисовка; no-op, если группа уже развёрнута). Пути: карточка на шапку свёрнутой группы (HTML5-дроп + pointer-путь), выделенный батч (place-tabs), вкладка правой рейки на шапку группы (`saveBtToGroup`) и в секцию свёрнутой группы (ghost-слот, `saveBtToCenter`/`place-tab`). Дроп-семантика и one-shot-подавление ложного post-drop клика без изменений — группа разворачивается дропом и НЕ сворачивается ложным кликом (тесты: TestCollapsedGroupDropExpand 5 + обновлённые TestGroupBarDrop/TestPostDropClick*/TestDragGhostOverCollapsed).
- **Переезд между пространствами** — drag&drop карточки на чип пространства (groupId очищается — между пространствами группы не ездят).
- **Поиск** — фильтрация по имени, заголовку и URL прямо на странице — поле наверху левой рейки (полная ширина рейки; ≤760px — скрыто, иконная рейка); клавиша `/` фокусирует поле. URL на карточке не отображается, но ищется. «Ничего не найдено» показывается только при активном поиске — сворачивание групп (карточек нет, но поиска нет) его больше не триггерит.
- **Карточка вкладки** — 80px высотой (было 74px — волна высоты; имя вкладки СВЕРХУ карточки, нижняя зона зарезервирована под будущий контент): ширина карточки -20% к прежней — сетка `--card-min` 141px (было 176px; единственный регулятор ширины: `repeat(auto-fill, minmax(var(--card-min), 1fr))` — в ряд влезает больше карточек), имя — 11.5px (`--card-name-size` — имя и инлайн-поле rename), цвет имени — токен `--card-name`: светлая тема — как `--text`, тёмная тема — ЧУТЬ ТУСКЛЕЕ (`#b5ada6` против `--text: #f5f2ee` — ближе к `--text-muted`), комментарий внизу карточки — 9px моно (было 10px); фавикон 15×15 + имя (без строки URL, без дропдауна). Фон карточки `--card-bg` — чуть контрастнее фона страницы (обе темы), 1px-граница. Клик — открыть, двойной клик по имени — inline rename (Enter — сохранить, Esc — отмена), ✕ — удалить (с confirm), чекбокс — выбор: при hover или в выбранном состоянии чекбокс заменяет фавикон (img и буквенный fallback) на месте — 15×15-слот фавикона, имя не сдвигается; на выбранной карточке чекбокс виден и без hover, после unhover у невыбранной карточки возвращается фавикон; клик по нему выбирает/снимает карточку (панель «N выбрано» обновляется). Длинное имя переносится на 2-ю строку (`.tab-name`: `white-space: normal`, `display: -webkit-box`, `-webkit-line-clamp: 2`, `overflow: hidden`), при переполнении обрезается многоточием в конце 2-й строки; короткое имя — одна строка; `.cname` — `align-items: flex-start` + `margin-top` у фавикона, так что фавикон стоит на первой строке имени; карточка остаётся ровно 80px и ничего не выходит за её границы (URL-строки нет, комментарий — одна строка внизу).
- **Редактирование вкладки (имя / адрес / комментарий)** — ✎ на карточке (hover-only, снизу-справа) открывает модалку по центру СРАЗУ — окно вертикальное (выше, чем шире), крупнее общей `.modal` (min-width 300px, поля 14px, поля/заголовки шире отступами), тон текста полей — токен `--card-name` (тот же тон, что у имени вкладки); скоуп только `#edit-tab-modal` — модалка пространств прежняя; промежуточное меню «Изменить» убрано полностью (нет ни JS-слоя меню, ни CSS `.tab-card-menu`) — с затемнённым фоном: поля имя/адрес/комментарий предзаполнены текущими значениями; Enter — сохранить, Esc / «Отмена» — закрыть; клик по затемнённому фону НЕ закрывает модалку (выделение текста в поле уносит указатель за окно — форма не схлопывается, значения в полях сохраняются). Пустое имя или адрес — старое значение сохраняется, пустой комментарий — комментарий очищается (ключ `comment` удаляется из записи). Сохранение шлёт `update-tab` в background; комментарий отображается внизу внутри карточки (моно, обрезается). Клик по ✎ не открывает вкладку и не стартует drag.
- **Настройки (модалка + FAQ)** — кнопка «Настройки» в левой рейке (был no-op-плейсхолдер, title «Скоро — настройки») открывает модалку `#settings-modal` (`.modal-overlay`; скоуп-стили как у `#edit-tab-modal` — крупнее общей `.modal`: min-width 340px / max-width 420px; только токены `var(--…)` — светлая и тёмная темы): заголовок «Настройки», крестик закрытия `.modal-close` сверху справа, раздел «Частые вопросы» (`.settings-section-title`) и 5 Q&A (`.faq-item` = вопрос `.faq-q` + приглушённый ответ `.faq-a`): что такое BlatTabs / как сохранить открытую вкладку (drag из правой рейки в центр, между группами) / пространства и группы / выгрузка-загрузка данных (Экспорт/Импорт JSON в левой рейке) / где хранятся данные (chrome.storage.local; синхронизация между устройствами — вместе с аккаунтом). Закрытие: ✕, клик по затемнённому фону и Escape — через `setModalOpen('settings')`, поэтому глобальный keydown (modal check → Escape → editable-guard) не перехватывает клавиши, пока модалка открыта.
- **Цвет вкладок (кастомный цвет карточек)** — в модалке настроек раздел «Цвет вкладок» между «Фоном» и «Частыми вопросами»: нативный пикер (#tab-color-input; дефолтное значение — фон карточки темы из токена `--card-bg` — подставляется при init и при открытии модалки) + «Сбросить» (#tab-color-reset, виден только при установленном кастомном цвете). Цвет — hex — пишется в `blattam-tab-color` (chrome.storage.local) и применяется live: `documentElement.style.setProperty('--tab-card-bg', hex)` — новый токен в обеих темах `theme.css` (значения как у `--card-bg`), которым `.tab-card` использует для фона; «Сбросить» — ключ удаляется и `removeProperty` (возвращается токен темы). Применяется при init (до первого рендера) и в `chrome.storage.onChanged` (local, идемпотентно, без перерисовки карточек — цвет живёт в инлайн-стиле documentElement). Выбранная карточка по-прежнему `--selected-bg`.
- **Фон (кастомная картинка)** — в модалке настроек раздел «Фон» над «Частые вопросы»: «Выбрать картинку» (#bg-file-btn → скрытый #bg-file-input, accept="image/*") читает файл через FileReader в data URL; data URL длиннее 4 000 000 символов — alert «Картинка слишком большая (максимум ~4 МБ)» и без сохранения; иначе — запись `blattam-bg-image` (chrome.storage.local) и применение: на document.body и #center-pane (центр имеет собственный непрозрачный --bg, перекрывающий body — поэтому инлайн-фон на обоих) background-image url(data) + background-size: cover + background-position: center + background-attachment: fixed (background-color темы остаётся под картинкой — фон виден в обеих темах). При установленном фоне в разделе появляются превью (#bg-preview, 64px, cover, --card-radius) и «Убрать» (#bg-clear-btn; без фона — скрыты); «Убрать» — ключ удаляется, инлайн-фон снимается. Применяется при init ДО первого рендера (как тема — переживает перезагрузку) и в chrome.storage.onChanged (локальная запись blattam-bg-image: применение/снятие при внешней записи, в т.ч. из другого окна) — идемпотентно, без перерисовки карточек.

- **Drag & drop (reorder)** — BlatTabs-style: забрали карточку — она исчезает из слота (на её месте — заглушка ghost-slot, см. ниже); за курсором следует нативный drag-образ браузера (клон-призрака нет); ЕДИНСТВЕННЫЙ индикатор вставки — сама заглушка (2px-линия `var(--ink)` из перетаскивания карточек убрана). Работает при любом фильтре (позиция считается по якорям в полном массиве 'blattam-tabs'); дроп в тот же слот и ту же группу — no-op, dragend без drop — карточка возвращается в слот и без следов. На чипе пространства преимущество его семантики (в пространство); дроп карточки на шапку группы — no-op, если у группы есть видимые карточки; шапка пустой/свёрнутой группы и слот-заглушка пустой группы принимают карточку (заглушка над ними морозится, над слотом и армед-шапкой не бегает). Нативный HTML5 DnD, без внешних библиотек.
- **Drag & drop (reorder): ghost-slot (заглушка слота)** — при захвате карточки на её месте в сетке появляется ghost-заглушка того же размера и скругления (тёплый тон: фон `var(--ghost-bg)`, пунктирная граница `var(--ghost-ring)`; пустая, не draggable, прозрачная для курсора — `pointer-events:none`); заглушка следует за мышью в потенциальный слот вставки с учётом секций (начало/середина/конец группы, конец списка — на границе секций по позиции курсора относительно середины шапки группы: выше середины — конец предыдущей группы, ниже — начало текущей; заглушка якорится ПОСЛЕДНЕЙ карточкой предыдущей секции (никогда «перед» шапкой следующей: при прогоне свёрнутых групп между секциями заглушка не встаёт в пространство низкой свёрнутой группы — она не «раскрывается» с призрачной вкладкой); соседние карточки сдвигаются естественным reflow сетки), нативный drag-образ браузера следует за курсором (клон-призрака нет); при отпускании вкладка заменяет заглушку и встаёт в позицию её слота в полном 'blattam-tabs', а если заглушка в другой группе — вкладка переезжает в ту группу (groupId обновляется; негрупповая секция — groupId становится null); дроп на чип пространства — move-поведение без изменений; дроп на шапку группы с видимыми карточками — no-op; на шапку пустой/свёрнутой группы и на слот-заглушку пустой группы («Перетащите вкладку сюда») — вкладка в группу (place-tab, anchorIndex null — в конец списка; своя группа — no-op), над чипом пространства заглушка замирает (над шапкой/слотом — прячется целиком, см. «Drag-layout» ниже); заглушка убирается на dragend; drag без drop — карточка возвращается в свой слот, заглушка убирается, storage не тронут; перерисовка (storage.onChanged) во время drag — заглушка убирается аккуратно. Число строк: схваченная карточка выдёргивается из сетки (inline display:none), и ghost-slot того же размера занимает её клетку (сразу после карточки) — пока заглушка в исходной секции, число строк секции не меняется и список под ней не сдвигается; когда заглушка уходит в другую секцию, карточки закрывают высвобожденный слот естественным reflow без «дырки»; последняя строка, которая бы схлопнулась (секция теряет ряд видимых карточек, например группа с одной вкладкой), ДЕРЖИТСЯ невидимой заглушкой-холдером `.tab-row-keeper` (см. «Drag-layout: строка исходной секции не схлопывается» ниже) — шапка группы при этом остаётся вооружённой целью дропа (groupVisibleCardCount); на dragend/Escape карточка возвращается в свой слот без следов.
- **Drag-layout: рефлоу слота и заглушка скрыта ЦЕЛИКОМ над шапкой/слотом** — при захвате карточки и уходе заглушки от её слота соседние карточки ЗАКРЫВАЮТ высвобожденный слот естественным reflow сетки (пустой «дыры» на месте карточки нет); число строк исходной секции при этом фиксировано: его держит сама заглушка, занимающая клетку выдернутой карточки — группы/вкладки под секцией не сдвигаются во время быстрого драга (последняя строка, которая бы схлопнулась, держится невидимой заглушкой-холдером `.tab-row-keeper` — см. «Drag-layout: строка исходной секции не схлопывается» ниже). Над шапкой ЛЮБОЙ группы (`.gbar` — развёрнутую, свёрнутую или пустую) и над слотом пустой группы (`.group-empty-slot`) заглушка прячется ЦЕЛИКОМ (`display:none` — её ячейка сетки освобождается: ни «тёплая» заглушка на старом месте, ни «дырки» — сетка перетекает), освобождённая ячейка заглушки закрывается reflow (число строк не меняется, пока в секции хватает карточек); заглушка остаётся в DOM и ВЕРНУЕТСЯ (display:''), когда курсор снова попадает в список (честный слот вставки). Пустые полосы карточной сетки (не сами шапки) — всех секций: (A) между низом шапки секции (.gbar / .loose-label / верх списка) и верхом её первой видимой строки; (B) между низом последней видимой строки и верхом шапки следующей секции (включая ниже последней строки последней секции, до «+ Группа»); (C) вертикальный зазор сетки (row-gap) между двумя строками карточек внутри секции — заглушка прячется целиком (display:none, как над шапкой): строки исходной секции держит условный row-keeper, а дроп в полосу — отмена (вкладка возвращается в исходный слот, без записи в storage и без reorder, оба пути драга: HTML5 и pointer). Не полосы (поведение не меняется): над .tab-card, над самой .gbar (дроп — в группу), над .group-empty-slot, пустые ячейки своей строки незаполненного ряда (заглушка видима в потенциальном слоте), чипы пространств, правая рейка, #spaces-bar. Над чипом пространства заглушка, как и раньше, замирает. Семантика дропа: дроп в пустую полосу — отмена (вкладка возвращается в исходный слот, storage не меняется), дроп на шапку пустой/свёрнутой группы — вкладка в группу (place-tab, anchorIndex null), группа разворачивается (post-drop-клик подавлен — не сворачивает обратно), дроп на шапку с видимыми карточками — no-op.
- **Drag: единственный вкладка/вкладка «одна в группе» — домашний слот, дроп домой no-op** — когда в группе ровно одна вкладка (или единственная негрупповая), во время драга секция читается «пустой» (карточка скрыта) и геометрия прыгала через её полосу в соседнюю секцию: в момент захвата заглушка уезжала в соседнюю группу, а дроп домой менял группу/позицию — вкладку было невозможно вернуть на место. Теперь: пока курсор в полосе исходной секции (от низа её шапки до верха шапки следующей), заглушка остаётся в слоте схваченной карточки (домой, видима, не уезжает), а вкладку «несёт» нативный drag-образ браузера; дроп домой — точный no-op (позиция в 'blattam-tabs' и groupId не меняются). Механизм (view.js): `slotIsSourceHome(clientY)` в `slotAnchor` (домашний якорь `{el: dragSourceCardEl, side:'after'}`) + guard в `placeCardToSlot` (якорь — сама исходная карточка, сторона «после» → no-op). Шапка/слот СВОЕЙ группы, multi-tab-секции и дроп в другую группу — без изменений (TestOnlyTabHomeDrop).
- **Перенос выделенного батча** — перетащил карточку, входящую в выделение (чекбоксы, >1 вкладки), — уезжают ВСЕ выделенные вкладки: в рендере — как перенос одной вкладки (скрывается только захваченная карточка, заглушка одна, клон-призрака нет); батч встаёт блоком на позицию слота в исходном порядке вкладок (`place-tabs` в background: вырезка из полного массива 'blattam-tabs', вставка перед/после якорной вкладки или в конец; группа — группа целевой секции, пространство не меняется); на шапку/слот пустой/свёрнутой группы — батч целиком в группу (если хотя бы одна вкладка не там), на чип пространства — каждая вкладка батча переезжает в пространство (группы очищаются); если порядок и группы не меняются (якорь — член батча) — no-op, сообщение не шлётся; не-выделенная карточка уезжает одна (place-tab).
- **Drag: плавное перемещение карточки (pointer-путь, «ощущение Toby»)** — в реальном Chrome перетаскивание карточки работает по механике Toby: движение больше 8 px от захвата (нативный drag-образ и HTML5-лента отменяются — trusted dragstart гасится) — схваченная карточка выдёргивается из сетки (inline display:none, computed opacity 1 — тёплая ghost-slot того же размера сразу после неё, в её клетке), под курсором клон карточки (`.pd-clone`, `position:fixed`, scale 1.02 + тень) 1:1, соседи сдвигаются FLIP-слайдом 200 ms, отпускание — синхронный коммит (семантика дропа прежняя: слот/группа/чип) + клон «приземляется» в цель за 180 ms (fade + scale 0.96); Escape или отпускание вне цели — отмена без записи; пересечение другой карточки во время драга не крадёт drag-source и не прячет её; обычный click (без движения) по-прежнему открывает вкладку; параметры — `window.blatamFx` (`slideMs`/`settleMs`/`liftScale`, 0 — эффект выключен); синтетический HTML5-путь (dragstart/dragover/drop/dragend харнесса) без изменений
- **Drag чипа пространства: плавное перемещение (pointer-путь)** — в реальном Chrome перетаскивание чипа пространства работает по той же механике, что и драг карточки: движение больше 8 px от захвата — оригинал исчезает из ряда (тёплая `.space-ghost-slot` в его месте, создаётся синхронно при захвате), под курсором клон чипа (`.pd-clone`, `position:fixed`, scale 1.02 + тень) 1:1, ghost-slot ходит по ряду (до/после чипа по половине, FLIP-слайд соседей 200 ms; над самим рядом — держит DOM-позицию), отпускание — синхронный коммит (над чипом — reorder по половине, над зазором ряда/«+ Пространство» — текущая позиция заглушки, в остальном — отмена без записи), клон «приземляется» в цель за 180 ms (fade + scale 0.96); Escape или отпускание вне ряда — отмена; дроп в собственный слот — no-op (без записи); обычный клик (без движения) по-прежнему переключает пространство; путь карточка→чип (перенос вкладки в space) и заморозка заглушки над чипом не тронуты; чип-путь переиспользует хелперы карточного пути (`pdCreateClone`/`pdFinishClone`/`applyFlipFrom`, обобщённый `snapshotCardRects`) при своём состоянии `pcd`; gbar и рейка получили isTrusted-guard в dragstart (срабатывают, когда их pointer-путь в следующих волнах обрабатывает press — флаги gbarPointerPress/railPointerPress на pointerdown, — или чужой pointer-драг карточки/чипа пересекает элемент: pdForeignActive; trusted dragstart гасится и не крадёт drag-source) — реальные HTML5-драги пока не затронуты, синтетический путь харнесса без изменений
- **Драг рейки: плавное перемещение (pointer-путь)** — в реальном Chrome перетаскивание вкладки правой рейки (#browser-tabs-list) работает по той же механике, что и драг карточки/чипа: движение больше 8 px от захвата (нативный drag-образ и HTML5-лента отменяются — trusted dragstart рейки гасится guard-ом: `railPointerPress`, ставится на pointerdown, или чужой pointer-драг — `pdForeignActive()` включает `btl.armed`) — оригинал исчезает из рейки (тёплая `.bt-ghost-slot` на месте, синхронно при захвате), под курсором клон (`.pd-clone`, `position:fixed`, scale 1.02 + тень) 1:1, заглушка ходит по рейке midpoint-правилом с FLIP-слайдом соседей 200 ms; пересечение центрального списка — тёплая центральная заглушка (`.tab-ghost-slot`) следует за курсором по слотам (ensureCentralBtGhost + moveCentralBtGhost); отпускание — синхронный коммит по тем же целям, что HTML5-дроп: рейка — reorder (chrome.tabs.move по индексу РЕАЛЬНОГО окна из DOM-позиции заглушки с учётом newtab-слота + самосинхронизация рейки syncRailFromTabs), шапка/слот пустой группы — вкладка в группу, центр — новая сохранённая карточка в слоте заглушки, space-чип/в остальном — отмена без записей; центральная заглушка снимается ЯВНО после любого коммита/отмены (recommit в рейку — порядок окна уже обновлён, следов в #tabs-list нет); клон «приземляется» в цель за 180 ms (fade + scale 0.96), при cancel — возвращается в домашний слот; Escape — отмена посреди драга; обычный клик (без движения) по-прежнему открывает вкладку; у рейки своё состояние `btl` (не пересекается с pd/pcd) — переиспользуются хелперы карточного пути (pdCreateClone/pdCloneMove/pdFinishClone/applyFlipFrom, обобщённый snapshotCardRects)
- **Toby-feel wave 2: same-frame reflow + autoScroll (pointer-пути)** — FLIP на всех трёх pointer-путях (карточка/чип/рейка) переписан в стиле оригинального Toby-бандла (dnd-kit `useSortable`: постоянный transition `{duration:200, easing:"ease"}` + `transform` при каждом изменении drag-состояния): `applyFlipFrom` — после рефлоу для каждой смещённой карточки inverse-трансформ (визуал до рефлоу − layout; layout = rect после рефлоу минус вполёте-трансформ из `getComputedStyle`) применяется с `transition:none` + синхронный flush (`offsetHeight`), затем `transform <slideMs>ms ease` + `transform:''` — слайд стартует в том же кадре, что и рефлоу, при следующей смене якоря transition ретаргетируется из текущей промежуточной позиции (нет double-rAF/setTimeout — нет 33ms-замирания, нет телепортов на быстром драге); один transitionend-слушатель на элемент (`el.__flipClear`) снимает inline-transition только для последнего прохода; easing = `ease` (оригинал бандла), `slideMs` 200 (0 — flip выключен). AutoScroll (Toby: DndContext autoScroll): `pdAutoScrollAt`/`pdFindScroller` — во время вооружённого драга курсор в 40px от верхнего/нижнего края скроллящегося контейнера с курсором (ближайший предок `overflow-y: auto|scroll` + `scrollHeight > clientHeight`, fallback — исходный элемент) скроллит этот контейнер: линейный ramp, до 20px за pointermove; подключено в `pdOnMove`/`pcdOnMove`/`btlOnMove` перед track-вызовом (заглушка ре-анкорируется против пост-скролл-геометрии). Settle без изменений (180ms `cubic-bezier(0.22, 1, 0.36, 1)` + fade + scale 0.96). Тесты: TestTobyReflowFeel (5, реальный mouse + реальный CSS).
- **Схваченная карточка выдёргивается из сетки во время драга (yank-out)** — при перетаскивании карточки (HTML5 и pointer-путь) схваченная карточка выдёргивается из сетки (inline display:none, computed opacity 1): на её месте — тёплая ghost-slot того же размера (сразу ПОСЛЕ неё, занимает её клетку, следует за курсором), под курсором — клон карточки `.pd-clone` (pointer-путь) / нативный drag-образ (HTML5-путь); число строк исходной секции постоянно — заглушка занимает ячейку (размер карточки сносится до скрытия — у скрытой rect 0x0); секция, у которой бы схлопнулась последняя строка (например группа с одной вкладкой), держит её невидимой заглушкой-холдером `.tab-row-keeper` (см. «Drag-layout: строка исходной секции не схлопывается»), а шапка группы остаётся вооружённой целью дропа (groupVisibleCardCount); курсор на собственной строке ghost-заглушки — заглушка не прячется и сетка не схлопывается (строка заглушки внутри секции — не пустая зона), дроп с её строки вставляет вкладку ровно туда; drop/Escape — возврат без следов (тесты: TestDragCardOpaque (6), TestDragRowReflow (3), TestDragRowKeeper (4))
- **Drag-layout: строка исходной секции не схлопывается (условный row-keeper)** — при драге карточки, когда ghost-заглушка уезжает из исходной секции (в другую секцию ИЛИ прячется целиком над шапкой группы / слотом пустой группы / пустой зоной карт.области), последняя строка секции больше не схлопывается: пока число строк уменьшается, в хвоте секции держит её невидимая карточка-заглушка `.tab-row-keeper` (`opacity:0`, `pointer-events:none`) — после последней видимой карточки, после шапки группы, если карточек нет, или перед «+ Группа» в негрупповой секции, — поэтому группы/вкладки под секцией не сдвигаются во время быстрого драга; холдер подключается только когда заглушка не занимает клетку в исходной секции и число отрисованных строк без него меньше `rOrig = ceil(nFull/cols)` (nFull — все вкладки секции, включая схваченную): строка не схлопывается (7 вкладок → 6 видимых = всё ещё 2 строки) или заглушка ВНУТРИ секции — холдера нет; снятие — возврат заглушки в секцию, dragend/Escape, перерисовка; холдер не `.tab-card` — шапка группы с одной вкладкой остаётся вооружённой целью дропа (groupVisibleCardCount), семантика дропа не меняется (тесты: TestDragSourceRowHold (12), TestDragRowReflow::test_single_tab_group_keeper_holds_row)
- **Карточка → правая рейка: открыть сайт новой фоновой вкладкой** — перетаскивание сохранённой карточки (`.tab-card`) с дропом по ПРАВОЙ РЕЙКЕ (#rail-right / #browser-tabs-list) — сайт открывается НОВОЙ ФОНОВОЙ вкладкой браузера (`chrome.tabs.create({url, active: false})` прямо из view.js): сама сохранённая карточка НЕ меняется — без place-tab/place-tabs, без записи в `blattam-tabs`, карточка остаётся в своём слоте сетки. Оба пути драга: HTML5 (dragover preventDefault + drop рейки — только при установленном `dragSourceUrl`; собственный драг рейки, gbar/чип-дропы и глобальный document-дроп не тронуты) и pointer (новая ветка `commitCardDropAt`: `closest('#rail-right')` — открыть + снять заглушку, клон «приземляется» у курсора); выделенный батч — все выделенные URL открываются фоном; дроп вне рейки и вне #tabs-list — отмена (без вкладки, без смены данных). Тесты: TestCardDropToRail (4)
- **Правая рейка: тёплый тон при перетаскивании карточки (drop-here)** — при перетаскивании сохранённой карточки над ПРАВОЙ РЕЙКОЙ (#rail-right) рейка становится тёплой (фон `var(--rail-warm)` — новый токен в обеих темах, тёплая гамма ghost-слота — + 1px inset-контур `var(--ghost-ring)`) — визуально подсвечивает, что дроп откроет сайт новой фоновой вкладкой; тон ставится обоими путями драга (HTML5 dragover/dragleave/drop + pointer `trackCardDragAt` над рейкой) только при драге КАРТОЧКИ (не при собственном драге рейки и не при драге шапки группы) и снимается при уходе курсора, дропе и на dragend. Тесты: TestRailWarmOnCardDrag (9)
- **При перетаскивании карточки над правой рейкой призрак скрыт** — при перетаскивании сохранённой карточки над ПРАВОЙ РЕЙКОЙ (#rail-right) тёплая ghost-заглушка (.tab-ghost-slot) скрывается ЦЕЛИКОМ (display:none — та же обработка, что над шапкой группы / слотом пустой группы: ячейка освобождается, строку исходной секции держит условный row-keeper) — обоими путями драга (HTML5 + pointer); возврат курсора в список — призрак снова виден на месте вставки, дроп-семантика без изменений (сайт открывается новой фоновой вкладкой, карточка не тронута), без остатков при дропе/отмене. Тесты: TestGhostHiddenOverRail (5)
- **Drag: заглушка в группе с полными строками не доращивает новую строку (row-full wrap-hide)** — при перетаскивании карточки, если тёплая заглушка стоит внутри группы, чья до-переносная раскладка от заглушки получила бы НОВУЮ строку (видимые карточки группы + заглушка > строк до-переносной раскладки; считается от ПОЛНОГО числа карточек группы по allTabs активного пространства, включая перетаскиваемую: `rOrig = ceil(nFull/cols)`, скрытие при `visible + 1 > rOrig*cols`), крайняя видимая карточка группы временно скрывается (display:none) — число строк группы постоянное; драг ВНУТРИ группы ничто не скрывает (число карточек группы не меняется — новая строка не возникает; например 6 карточек / 5 колонок — 2 строки и до, и во время драга). Возврат крайней карточки: заглушка ушла из группы / скрыта (шапка группы, слот пустой группы, пустая зона карт.области) / конец драга / перерисовка; новая строка появляется только на реальном дропе (в группу уходит настоящая карточка). Только группы (негрупповая секция — как была). Механика (view.js): `updateWrapHiddenCard(anchor)` — вызыв из `trackCardDragAt` до `moveGhostSlot` (общий путь HTML5-и pointer-драга), трекеры `dragWrapHiddenCard`/`dragWrapHiddenGroup`. Тесты: TestDragGroupFullRowWrapHide (7)
- **Карточка сохранённой вкладки — 80px (волна высоты, было 74px)** — min-height `.tab-card` 74px → 80px (только `<style>` view.html — единственный источник высоты); слот-заглушка пустой группы `.group-empty-slot` синхронизирован (высота = карточка, 80px); тёплая ghost-slot при драге берёт высоту с карточки на рантайме (view.js не тронут). Тесты: TestTabCardHeightTaller (2) + геометрия перекалибрована (±0.6). Итого 532 unit-тестов
- **Массовое открытие** — чекбокс на карточке (кнопка «Выбрать»-select-all из мета-строки удалена) → плавающая панель внизу: «Открыть» открывает вкладки (неактивные), «Сбросить» — снять, «✕ Удалить» — массовое удаление выделенных: один confirm («Удалить N вкладку/вкладки/вкладок?» — правильные русские формы), на OK — все выбранные вкладки удаляются одной записью в storage, выбор снимается (пустой выбор — no-op, отмена — без изменений). Клик по открытой вкладке или изменение storage сбрасывает выбор. Выбранная карточка — темнее и бордовее: фон `var(--selected-bg)` (токен в обеих темах: светлая — `#efe8e9`, тёмная — `#2e2325` — темнее карточки, с бордовым оттенком) + деликатное бордовое 1px-кольцо `var(--selected-ring)` (светлая — `rgba(107, 16, 32, 0.25)`, тёмная — `rgba(222, 120, 138, 0.30)`) — заметнее обычной границы `--line`, но мягче сплошного чернила; чекбокс выбора — контурный (не сплошное чернило): фон `var(--surface)` + 1px-контур и галочка в бордовом `var(--selected-check)` (светлая — `rgba(107, 16, 32, 0.90)`, тёмная — `rgba(230, 145, 160, 0.95)`) — менее бросается в глаза.
- **Клавиатурная навигация** — стрелки по карточкам (зациклено, в пределах текущего фильтра; ↓/→ от ничего — первая, ↑/← от ничего — последняя), Enter — открыть активную, Delete/Backspace — удалить (с подтверждением), Esc — сбросить поиск/выбор/активную карточку (работает и из поля ввода). Активная карточка подсвечена монохромным контуром.
- **Горячая клавиша** — Ctrl+Shift+S (блок `commands` в manifest: `save-tab`, suggested key «Ctrl+Shift+S», description «Save current tab») — сохраняет текущую вкладку так же, как popup: в пространство по умолчанию (`blattam-last-space` → первое → «Мои вкладки»); дедупликация по URL + space; chrome:// URL пропускаются.
- **Фавикон на карточках** — общий save-путь в background.js захватывает `tabs.favIconUrl` и кладёт его полем `favIconUrl` в сохранённую вкладку (саму иконку не скачиваем — URL-адрес загружается прямо в `<img>`). На карточке — маленький `<img class="tab-favicon">` (15×15, 1px-граница `var(--line)`, скругление 3px, `object-fit: contain`) перед именем; если `favIconUrl` отсутствует или картинка не загрузилась (onerror) — монохромный буквенный fallback-тайл с первой буквой домена (`var(--hover)`/`var(--text-muted)`, обе темы). Импорт: `favIconUrl` у вкладок сохраняется; экспорт: едет обычным полем; вкладки без фавикона рендерятся с fallback.
- **Удаление** — клик по ✕ на карточке (с подтверждением).
- **Экспорт / импорт JSON** — «↓ Экспорт» / «↑ Импорт» в шапке: JSON с вкладками + пространства + группы; импорт дедуплицирует пространства/группы по имени и вкладки по URL; файлы legacy-формата (с `folders`) мигрируются по тем же правилам, что и storage.

## Сообщения между компонентами

| Действие | Откуда → Куда | Описание |
|---|---|---|
| `save-current` | popup/hotkey → background | Сохранить текущую активную вкладку (spaceId → по умолчанию) |
| `add-tab` | view/popup → background | Создать запись вручную (имя + URL) |
| `open` / `delete` | popup/view → background | Открыть/удалить вкладку по индексу |
| `open-one` / `open-many` | view → background | Открыть одну / несколько вкладок (пачкой — без активации) |
| `move-tab` | view → background | Перемещение: spaceId (в другое пространство, groupId очищается) и/или groupId (null — «Без группы») |
| `rename-tab` / `reorder-tab` | view → background | Переименование / reorder |
| `update-tab` | view → background | Редактирование вкладки: имя/адрес/комментарий (пустые имя/адрес → старые значения, пустой комментарий → удалить ключ) |
| `place-tab` | view → background | Дроп вкладки в позицию ghost-слота: позиция по якорю (перед/после вкладки; конец секции — после последней вкладки этой секции) + groupId секции заглушки (null — «Без группы»); тот же слот и та же группа — no-op; `anchorIndex: null` — в конец списка (дроп на шапку/слот пустой или свёрнутой группы) |
| `create-space` / `delete-space` / `rename-space` | view/popup → background | CRUD пространств |
| `create-group` / `delete-group` | view → background | CRUD групп (удаление: вкладки остаются в пространстве) |

**Автообновление view/popup:** `chrome.storage.onChanged` — все открытые newtab-страницы и popup реагируют на изменения storage без сообщений (popup дополнительно синхронизирует выбранное пространство с `blattam-last-space` и подсвечивает только что созданное пространство).

## Стили и UI

- **Vercel-моно-дизайн** (Geist, 1px-границы, монохром): фон `#fff`, карточки `#f5f5f5` (`--card-bg`, чуть контрастнее фона страницы), шапка/модалки/шапки групп `#fff` (`--surface`), 1px-границы (через box-shadow `0 0 0 1px var(--line)`), текст `#171717`, приглушённый `#666`, hover `#fafafa`. Единственный «акцент» — чернильное чёрное (`--ink`): чёрные кнопки («Открыть», «Сохранить вкладку»), активные чипы, клавиатурный фокус, подсветка drop-over. Радиусы 6–8px, тени только на hover. Плотность карточек всегда компактная (без переключателя размера).
- **Шрифт** — Geist (Google Fonts-ссылка в view.html/popup.html) + системный fallback `system-ui`; для счётчиков и keycaps — Geist Mono.
- **Дизайн-токены** — в `theme.css` (CSS-переменные на `:root`): фоны, поверхности, текст, границы, чернило, тени, геометрия карточек, шрифты. view.html и popup.html включают его через `<link rel="stylesheet" href="theme.css">` и используют только `var(--*)` в своих `<style>`-блоках — без захардкоженных hex в стилях разметки.
- **Тёмная тема** — toggle-кнопка 🌙/☀️ в шапке view.html; состояние хранится в `chrome.storage.local` под ключом `blattam-theme` ('dark'/'light', по умолчанию светлая). view.js читает сохранённую тему при init и ставит `document.documentElement.dataset.theme` **до первого рендера** (страница не мигает). Тёмные значения токенов — в `[data-theme="dark"]` в `theme.css` (светлее и теплее: нейтрально-тёплая приглушённая палитра с повышенным контрастом, не «чёрное на чёрном» — bg `#1f1c1b`, поверхности `#2a2624`, карточки `#36312d`, граница `rgba(255,255,255,.10)`, текст `#f5f2ee`, приглушённый `#a8a09a`; чернило — светлое `#f5f2ee`). Остальные стили править не нужно — только `var(--*)`.
- **Тёплый акцент: заглушка перетаскивания** — при перетаскивании карточки оригинал исчезает из слота; в сетке единственный индикатор — тёплая пустая заглушка (`.tab-ghost-slot`, размер карточки: фон `var(--ghost-bg)` + 1px пунктирный контур `var(--ghost-ring)`) — стоит в слоте карточки и ходит за курсором к позиции вставки, дроп ставит карточку на её место. Клон-призрака нет: за курсором следует нативный drag-образ браузера. Токены `--ghost-bg`/`--ghost-ring` в обеих темах `theme.css` (light `#fbe3b6`/`#d99a4e`, dark `#4c3c22`/`#d7a24d`) — в `<style>` только `var(--*)`, без hex.
- **Шапка группы «Штрих»** — `.gbar`: полноширинная строка 26px БЕЗ заливки: 1px-линия сверху — оверлей `::before` из `--gbar-top-line` (светлая — сплошная `--line2`, тёмная — градиент, тускнеет к краям), chevron `--text-faint`, имя 12px/500 `--text-soft`, mono-счётчик `--text-faint`; hover — лёгкий фон `--gbar-hover` (светлая — `--hover`, тёмная — едва заметный) + контролы (☑ ✎ ✕); клик — сворачивание группы (счётчик остаётся, состояние в данных).

Драг вкладки рейки в центральный блок — сохранить карточкой в позиции ghost-slot (группа секции или «Без группы»): при драге по центральному списку видна тёплая заглушка-слот вставки (`.tab-ghost-slot`, размер карточки, тот же тон, что у драга карточки) — встаёт в потенциальный слот и следует за курсором (view.js: `ensureCentralBtGhost`/`moveCentralBtGhost`); браузерная вкладка остаётся открытой, зеркало не трогается.
